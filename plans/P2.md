## 0. Scope and hard rules

P2 delivers:
- **E1 backend**: job states (FR-1.1); `report_extractions`, `extracted_rows`, `extraction_edits` and the
  `sign_offs.job_id` unique constraint (FR-1.2, FR-9.1); an extraction-only report task with needs_review triggers
  (FR-1.3); the review API (FR-1.4); sign-off and QR gated on a confirmed extraction (FR-1.5).
- **E1 UI**: the Review screen (FR-1.6) and the dashboard review queue (FR-1.7), in the in-browser-Babel `ui/`.
- **E7**: provenance (`source_page`, `source_bbox`, `source_text`, `confidence`) from PyMuPDF word boxes, Paddle
  boxes and CSV rows (FR-7.1); "from page N" plus a confidence dot on the result page and in the PDF (FR-7.2).
- **FR-9.1**: one sign-off per job, proven by a real concurrency test against uvicorn.
- **Eval**: `ExtractedRowsAdapter` and the `confirmed_v1` scorer (P1 §14), the deferred judge tightenings (P1 review
  LOW-1, LOW-3, T16 F2), and two visible, attributable re-baselines.
- **Image upload** on the report route (`.png`, `.jpg`, `.jpeg`; P1 §14 item 5).
- **Legacy tests**: the two failing integration tests in `tests/test_rag_integration.py` (§10).

Hard rules:
1. **S1 is structural.** Exactly one function produces results (scores, flags, alerts, summaries that anyone can
   see): `score_confirmed_rows`, called in production only by the scoring task on rows a clinician confirmed. The
   extraction's preliminary engine pass feeds only the review triggers and the internal `prelim_flag` column, which
   no API returns (§5.3). Every read path that returns a score, flag, alert, summary, PDF, sign-off or QR goes
   through one choke point (`app/services/review/gate.py`, §5) that answers 409/403 unless the job is `completed`
   from a confirmed extraction. Static and runtime tests enforce all three (§12).
2. **The extracted row set does not change in P2.** Rows shown for review are exactly the rows the current product
   shows (engine `analysis.rows`, plus legacy urine rows under today's branch rules), plus unread lines. P2 adds
   needs_review, specimen, provenance and confidence, never different rows. This keeps the re-baseline attributable
   to review semantics (§9.5 states the one admissible, listed exception).
3. **The engine is not tuned in P2.** Allowed engine-adjacent changes, each proven output-neutral except (c):
   (a) tracing which physical lines a row came from, and returning unread-line texts;
   (b) carrying page/bbox through the column parser, and a `@row=N` meta token on structured-CSV lines;
   (c) one S5 floor: a row whose specimen is urine, CSF, fluid or other is never scored against a blood analyte's
       registry range or critical limits (§7.3). Default behaviour (specimen unset) is unchanged.
   Accuracy work (E2/E3, Appendix A) is P3.
4. **Never weaken** a metric definition, a safety assertion, Table C, a target or the heldout split. Judge changes in
   P2 only tighten. Never read heldout failures: `eval/corpus/heldout/`, `tools/eval/layouts/heldout/` and
   `tests/heldout/` are DO NOT READ for every P2 builder; repeat this sentence in every delegated prompt.
5. **No new runtime dependency.** One test-only dependency: the `playwright` Python package (AC-1.8 names
   Playwright), driving the system Chrome. It lives in a new `requirements-e2e.txt`, not in `requirements.txt`.
6. **No data loss.** The migration archives duplicate sign-offs before deleting them; downgrade restores them, and
   refuses to drop non-empty review tables unless explicitly allowed.
7. **S10 for new code.** No exception text, SQL, file paths or PHI in any response, WebSocket message or log line
   written by P2 code. Logs carry job ids and counts only.

Out of scope: engine and template accuracy (P3); FHIR/HL7 (P4); patient-language summaries and the trends chart (P5);
dead-module deletion FR-9.5 and the full probe-suite extension FR-9.6 (P6; P2 covers its own endpoints); README
rewrite FR-10.x (P7; P2 adds only a review-flow section, FR-9.3 partial).

### 2.2 Data flow (F1 in the PRD)

1. `POST /api/v1/analyze/report/{type}` validates and saves the file, inserts `async_jobs(status=queued)` and
   `report_extractions(job_id, file_path, file_kind, patient_id, sex, age, explanation_mode)`, **commits**, then
   dispatches `analyze_report_task` (queue `reports`). Dispatch failure → status `failed`, 503.
2. The extraction task CAS-sets `queued|extracting → extracting`, calls `extract_report`, then in **one
   transaction** inserts all rows, writes page geometry, warnings and OCR confidence, and CAS-sets
   `extracting → awaiting_review`. It never scores and returns only `{job_id, status, rows, needs_review}`.
3. The clinician reviews: `GET extraction`, `GET pages/{n}.png`, `PATCH rows/{row_id}`, `POST rows`.
4. `POST confirm`, one transaction under a row lock: refuse (409) if any needs_review row is `pending`, if the
   revision is stale, or if nothing would be scored; mark the remaining `pending` rows `accepted` (audited); stamp
   `confirmed_by/at`; set `awaiting_review → scoring`; commit; dispatch `score_report_task`; 202.
5. The scoring task loads the confirmed rows (`kind=row`, `status ∈ {accepted, edited, added}`), calls
   `score_confirmed_rows`, and in one transaction upserts `reports` (keyed by `celery_task_id = job_id`) and sets
   `scoring → completed`. It returns only `{job_id, status}`.
6. Result, PDF, sign-off, QR, history and WebSocket results read through `review/gate.py`.

### 2.3 Dependency rule

`app/services/review/*` may import `app.services.lab_engine`, `app.services.ocr_service`, `app.services.preprocessor`,
`app.pipeline` helpers and `app.models`. The engine (`lab_engine/*`) imports nothing from `review`. `extract.py` and
`scoring.py` import no DB module except `scoring.py`'s optional history reader (injected as a callable so the eval
calls it with none). `tools/eval/adapters/extracted_rows.py` imports `app` lazily, as v0 does; judge and GT modules
never import `app` or the adapters (GN-11 stays green).

Two mechanical rules keep the existing tests and spies working:
- `app.pipeline.run_report_pipeline` imports `review.extract` and `review.scoring` **inside the function** (they
  import helpers from `app.pipeline`; a module-level import would be circular).
- `review/scoring.py` and `review/extract.py` call pipeline and engine helpers **through module attributes**
  (`from app import pipeline as _pl` … `_pl.predict_tabular(...)`, `_pl.analyze_lab_rows(...)`,
  `_pl._explain_report_safe(...)`), never through names bound at import time, so the many existing
  `monkeypatch.setattr(pipeline, ...)` tests and the eval's spies and stubs still intercept them.

### 3.4 Migration `c4f1e2d3b5a6_p2_review_flow` (single head; reversible; lossless for existing data)

Upgrade, in order:
1. Create `report_extractions`, `extracted_rows`, `extraction_edits` with the constraints above (names follow the
   `app/db/base_class.py` convention, via `op.f(...)`).
2. Create `sign_off_duplicates_archive` (`id` UUID PK, `job_id`, `clinician_id`, `model_versions`, `signed_at`,
   `archived_at` default now()).
3. Archive duplicates, keeping the **earliest** sign-off per job (PRD FR-1.2):
   `INSERT INTO sign_off_duplicates_archive (id, job_id, clinician_id, model_versions, signed_at)
    SELECT id, job_id, clinician_id, model_versions, signed_at FROM sign_offs
    WHERE id NOT IN (SELECT DISTINCT ON (job_id) id FROM sign_offs ORDER BY job_id, signed_at ASC NULLS LAST, id ASC)`;
   then `DELETE FROM sign_offs WHERE id IN (SELECT id FROM sign_off_duplicates_archive)`.
4. Drop `ix_sign_offs_job_id`; create `uq_sign_offs_job_id` UNIQUE (`job_id`).
5. No backfill: pre-P2 report jobs have no `report_extractions` row and are treated as legacy-unconfirmed (§5.4).

Downgrade, in order:
1. Guard: if `extracted_rows`, `extraction_edits` or `report_extractions` holds any row and the environment variable
   `VAIDYA_ALLOW_LOSSY_DOWNGRADE` is not `1`, raise with a clear message (nothing changes).
2. Drop `uq_sign_offs_job_id`; recreate `ix_sign_offs_job_id`; re-insert the archived rows into `sign_offs`; drop
   the archive table. The pre-upgrade `sign_offs` is restored exactly.
3. Drop the three review tables.

`SignOff.job_id` becomes `mapped_column(String(64), nullable=False, unique=True)` (no `index=True`), so ORM metadata
equals the migrated schema (MG-05).

### 3.5 Job state machine (`review/states.py`; report jobs)

| From | To | Actor | Mechanism |
|---|---|---|---|
| — | `queued` | upload route | insert `async_jobs` + `report_extractions`, commit, then dispatch |
| `queued` | `failed` | upload route | dispatch raised (503 to the client) |
| `queued`, `extracting` | `extracting` | extraction task start | CAS; idempotent so Celery retries work |
| `extracting` | `awaiting_review` | extraction task | same transaction as the row inserts |
| `queued`, `extracting` | `failed` | extraction task (invalid file, or retries exhausted in `on_failure`) | CAS |
| `awaiting_review` | `scoring` | confirm route | job row lock; same transaction as implicit accepts and the stamp |
| `scoring` | `awaiting_review` | confirm route | dispatch raised; stamp cleared |
| `scoring` | `completed` | scoring task | same transaction as the `reports` upsert |
| `scoring` | `failed` | scoring task (retries exhausted) | CAS; rows and edits kept |
| `completed` (no sign-off) | `awaiting_review` | reopen route | job row lock; `reports.status = SUPERSEDED`; stamp cleared |
| `failed` (stamp set) | `awaiting_review` | reopen route | job row lock |

Every other transition is refused (`InvalidTransition` → 409 at the API). Progress shown by `GET /jobs/{id}`:
queued 0.0, extracting 0.25, awaiting_review 0.5, scoring 0.75, terminal 1.0. `low_quality` is kept for image jobs and
never produced by report jobs.

## 4. API (all under `/api/v1/jobs`, owner-only, 404 otherwise; error shape unchanged)

### 4.1 Common rules

- Ownership: `Depends(require_job_owner)` with path parameter `task_id`; the job must also have
  `pipeline == "report"`, else 404. Admins who do not own the job get 404. No token → 401.
- A `row_id` must belong to the job in the path; otherwise 404 (never reveals another job's row).
- Every write takes `SELECT … FROM async_jobs WHERE id = :id FOR UPDATE` first, so writes, confirm, reopen and
  sign-off serialise per job.
- Writes allowed only in `awaiting_review`: `queued|extracting` → 409 `EXTRACTION_NOT_READY`;
  `scoring|completed|failed|low_quality` → 409 `EXTRACTION_LOCKED`.
- Legacy report jobs (no `report_extractions` row) → 409 `NO_EXTRACTION` ("analysed before review was available;
  upload it again to review").
- Responses carry `Cache-Control: no-store`, except the page image (§4.3).
- Error messages are fixed strings; no exception text (S10).

### 4.2 `GET /{task_id}/extraction` → 200

```
{ job_id, status, review_state: "needs_review"|"ready_to_confirm"|"confirmed"|"not_ready",
  revision, file_kind, page_count, pages: [{n, width, height, unit, method, rotation}],
  patient: {sex, age}, warnings: [str], notes: [str],
  counts: {rows, unread_lines, needs_review, pending_review, accepted, edited, added, deleted},
  unread_lines: [row_id, ...],  review_all,
  rows: [ {row_id, row_index, kind, status, version, name_raw, analyte_key, analyte_display, value_raw, value_num,
           qualifier, text_value, unit_raw, ref_low, ref_high, ref_text, printed_flag, specimen, confidence,
           needs_review, review_codes, review_reason, origin, source_page, source_bbox, source_text,
           edits: [{field, old_value, new_value, at, user_id, username}] } ],
  confirmed_at, confirmed_by }
```
- Rows in `row_index` order (the UI sorts). `pending_review` = rows with `needs_review` and `status = pending`
  (unread lines included). `review_state`: `not_ready` (queued, extracting, failed before confirmation);
  `ready_to_confirm` (awaiting_review, `pending_review == 0`, at least one confirmable row); `needs_review`
  (awaiting_review otherwise); `confirmed` (`confirmed_at` set). `review_all` (bool) is returned with its warning.
- **Never** returns `prelim_flag`, `risk_*`, `anomalies`, alerts, explanations or summaries (S1-2 allowlist test).
  The review reason "Looks critical — please verify" is the only signal of the engine's critical assessment
  (FR-1.6 names it).

### 4.3 `GET /{task_id}/pages/{n}.png?scale=` → 200 `image/png`

- Route path `"/{task_id}/pages/{n:int}.png"`; `n` is 1-based; `n < 1` or `n > page_count` → 404 `PAGE_NOT_FOUND`;
  CSV jobs → 404. Missing source file → 404 `SOURCE_FILE_UNAVAILABLE`.
- `scale` default 1.5 (PDF) / 1.0 (image); clamped to [0.5, 3.0] and rounded to 0.25; output capped at 4000 px on
  the long side. PDF: `page.get_pixmap(matrix=fitz.Matrix(scale, scale))` (renders the rotated page, so pixel =
  point × scale in the displayed space). Image: Pillow `ImageOps.exif_transpose`, resize by `scale`, re-encode PNG
  (strips EXIF, including GPS).
- Disk cache `uploads/pages/<job_id>/p<n>@<scale>.png` (git-ignored). Headers: `Cache-Control: private,
  max-age=3600`, `ETag` = SHA-256(file SHA-256, n, scale, renderer version), `X-Content-Type-Options: nosniff`;
  `If-None-Match` match → 304. Allowed in every job state (the clinician may look at the source after confirm).

### 4.4 `PATCH /{task_id}/extraction/rows/{row_id}` → 200 (the updated row, `revision`, `counts`, `warnings`)

Body: `{version (required), name_raw?, value_raw?, unit_raw?, ref_low?, ref_high?, ref_text?, printed_flag?,
specimen?, status?: "accepted"|"deleted"|"pending"}`.
- Stale `version` → 409 `ROW_VERSION_CONFLICT`.
- Field validation (`rows.parse_value_input` and friends; 422 codes):
  - `value_raw`: number with optional qualifier `<,>,<=,>=,≤,≥`; a range result `a-b` (microscopy); a titre `1:N`;
    or a non-empty word/phrase (qualitative or info). A comma anywhere in a number → 422 `INVALID_VALUE`
    ("Use a decimal point, without thousands separators"). Non-finite or |x| ≥ 1e9 → 422.
  - `ref_low`/`ref_high`: finite floats or null; `ref_low ≤ ref_high` → else 422 `INVALID_RANGE`.
  - `name_raw`: 1–120 characters → else 422 `NAME_REQUIRED`. `analyte_key` is recomputed server-side
    (`match_analyte`, then the S5 floor for the row's specimen); not client-settable.
  - `unit_raw` ≤ 32 characters; `specimen` and `printed_flag` from their enums.
- Field changes on a `pending|accepted|edited` row set `status = edited`; on an `added` row keep `added`. An
  `unread_line` with field changes becomes `kind = row`, `status = edited` and must then have a name and a value
  (else 422 `VALUE_REQUIRED`); it keeps its provenance.
- `status` transitions (anything else → 422 `INVALID_TRANSITION`):

| From | `accepted` | `deleted` | `pending` (restore) |
|---|---|---|---|
| pending (row) | ✓ if `acceptance_errors` is empty | ✓ | — |
| pending (unread_line) | ✗ ("convert or dismiss") | ✓ (dismiss) | — |
| accepted | — | ✓ | ✓ |
| edited | — | ✓ | — |
| added | — | ✓ | — |
| deleted | — | — | ✓ → `edited` if the row has field edits, `added` if manual, else `pending` |

- `acceptance_errors(row)` (S6, patient-safe acceptance; also applied to the implicit accept at confirm):
  `VALUE_REQUIRED` (no `value_num` and no `text_value`); `UNIT_REQUIRED` (review code `NR-UNIT`: a count or
  unit-bearing analyte without a recognised unit — accepting it would score an assumed unit, S6); `SPECIMEN_REQUIRED`
  (code `NR-SPECIMEN` and specimen still `unknown`).
- Each changed field → one `extraction_edits` row (user, time, old → new); the row `version` and the extraction
  `revision` increment in the same transaction. Response `warnings` includes "Test name not recognised; it will be
  scored only against the range you enter" when the edited name has no `analyte_key`.

### 4.5 `POST /{task_id}/extraction/rows` → 201 (the new row)

Body: `{name_raw, value_raw, unit_raw?, ref_low?, ref_high?, ref_text?, specimen}` — `specimen` is **required**
(no default; a urine value defaulted to serum could fire a serum critical, S5). Creates `kind=row`, `origin=manual`,
`status=added`, `confidence=1.0`, `needs_review=false`, provenance NULL, `row_index = max + 1`,
`parsed_payload = build_manual_row(...)`; audited (§3.3); `revision` +1.

### 4.6 `POST /{task_id}/extraction/confirm` → 202

Body: `{revision}`. Under the job row lock:
1. status ≠ `awaiting_review` → 409 `JOB_NOT_AWAITING_REVIEW`;
2. `revision` stale → 409 `REVIEW_CHANGED` (the clinician confirms exactly what they saw);
3. any `needs_review` row with `status = pending` (unread lines included) → 409 `REVIEW_INCOMPLETE`
   with `{pending_review: n, row_ids: [...]}` (AC-1.2);
4. any pending non-review row failing `acceptance_errors` → 409 `REVIEW_INCOMPLETE` listing it (defensive; rules
   make this unreachable);
5. no confirmable row (`kind=row` and status `accepted|edited|added|pending`) → 409 `NOTHING_TO_CONFIRM`.
Then: pending non-review rows → `accepted` (edit rows `status: pending → accepted`, user = confirmer);
`confirmed_by/at` stamped; status → `scoring`; `AuditLog(action="report.extraction.confirm")`; commit; dispatch
`score_report_task` (Celery task id `"{job_id}:score:{revision}"`). Dispatch error → CAS `scoring → awaiting_review`,
clear `confirmed_at/by`, 503 `SCORING_UNAVAILABLE` (retryable). Response `{job_id, status: "scoring", poll_url}`.

### 4.7 `POST /{task_id}/extraction/reopen` → 200 (P2 addition)

Allowed when status is `completed` and **no sign-off exists**, or status is `failed` with `confirmed_at` set
(scoring failed). Under the job row lock: `reports.status = 'SUPERSEDED'` for the job, `confirmed_at/by` cleared
(the edit log and an `AuditLog(action="report.extraction.reopen")` keep the history), status → `awaiting_review`.
Signed jobs → 409 `ALREADY_SIGNED_OFF` (a signed report is immutable; amendments are a declared limitation). Other
states → 409 `REOPEN_NOT_ALLOWED`.

## 5. S1 read paths: the choke point

### 5.1 `app/services/review/gate.py`

- `async def require_confirmed_result(db, job: AsyncJobRecord) -> dict` (routes) and
  `def require_confirmed_result_sync(cur, job_id) -> dict` (worker history reader). Order of checks:
  1. `job.pipeline != "report"` → caller uses its legacy path (the gate raises `NotAReportJob`);
  2. status in `queued|extracting|awaiting_review|scoring` → 409 `EXTRACTION_NOT_CONFIRMED`;
  3. status ≠ `completed` → 409 `JOB_NOT_COMPLETE`;
  4. no `report_extractions` row or `confirmed_at IS NULL` → 409 `LEGACY_UNCONFIRMED`;
  5. no `reports` row with `celery_task_id = job.id` and `status = 'COMPLETED'` → 409 `RESULT_UNAVAILABLE`;
  6. return `reports.analysis_result`.
- `async def require_shareable(db, job_id) -> dict` = the above plus a sign-off row; failures map to 403
  `NOT_AVAILABLE` for the unauthenticated QR paths.

### 5.2 Writers of `reports`

Only the scoring task (`store.complete_scoring`) writes `reports` for report jobs; `PipelineTask.on_success` no
longer calls `upsert_report_result` for report tasks. A test asserts no `reports` row exists after extraction.

### 5.3 What leaves the server before confirm

Only: job status and progress; the extraction payload of §4.2 (extracted data, provenance, confidence, review
reasons; no computed flag); page images. Celery result payloads of both report tasks carry no values.

### 5.4 Legacy jobs (pre-P2 `completed` report jobs)

Their results were produced without confirmation, so they are **not** results under S1: result, PDF, sign-off and
QR answer 409 `LEGACY_UNCONFIRMED`; existing QR tokens answer 403; history and trends exclude them. Nothing is
deleted. Declared in DECISIONS.

## 6. Extraction and provenance

### 6.1 `extract_report(file_path, report_type, sex, age) -> ExtractionOutput`

`ExtractionOutput`: `status` (`ok`|`failed`), `error_code`, `file_kind`, `pages`, `rows: list[RowData]` (rows and
unread lines, document order), `warnings`, `notes`, `raw_text`, `ocr_confidence`, `extractor_version`.

Steps:
1. Validate the file (`_validate_file_safe`); invalid → `failed` / `FILE_INVALID`.
2. `run_ocr_with_layout(path)` → `(OcrOutput, DocumentLayout)`; `run_ocr` returns the same `OcrOutput` (identity).
3. PDFs: `_parse_column_lab_report_safe` (unchanged acceptance rule). If its rows are used: rows come from the column
   parser with its page/bbox (`origin=column`), no unread lines (today's behaviour, N1 is P3).
4. Otherwise `parse_report_text_traced(raw_text)` → rows with physical line ids, unread lines (ids, text).
5. Specimen per row (§6.5), written to `ParsedRow.specimen`.
6. Preliminary engine pass: `analyze_lab_rows(rows, sex, age, unparsed_numeric_lines=len(unread))`. Extracted rows
   are exactly `analysis.rows` in order (post-dedupe, as shown today), each linked to its `ParsedRow` by identity.
7. Legacy urine (when `detect_report_type(raw_text) == "urinalysis"`): `urine.legacy_rows(raw_text)` (Groq-or-regex
   entities via the first half of `run_urinalysis_pipeline`; **no KB query, no patterns** at extraction). Today's
   branch rule decides which rows are shown: no blood rows (`_is_blood_row` over the step-6 rows) → legacy rows
   **replace** engine rows; blood rows present → legacy rows whose `_lab_name_key` is not already shown are appended.
   Legacy rows: converted to `ParsedRow`s by `urine.legacy_to_parsed` (name, value or text, unit, `ref_text`,
   `section="urine examination"`, `specimen="urine"`), scored in a second preliminary `analyze_lab_rows` pass of
   their own (so step 6's rows are untouched), `origin=legacy_urine`, always needs_review; provenance located by text
   search (§6.3).
8. Provenance and confidence per row (§6.2–6.4); review codes (§6.6).
9. Report-level warnings: `analysis.warnings` not attributed to a shown row (`"<display_name>:"` prefix) and not the
   unread-line count message. Notes: the sex/age-not-provided sentence. **No row of kind `row`** (whether or not
   unread lines exist) → warning "No results could be read automatically. Check the whole report against the page
   and add each result." and `review_all = true` (status stays `ok`). This keeps the P1 meaning of review_all (v0:
   no lab values + "review it manually"): when nothing was parsed, the clinician is told to read everything, so a few
   unread lines never make the remaining rows look silently covered or silently missing.
10. Any exception → `failed` / `EXTRACTION_ERROR` (generic; the traceback goes to the log without values).

### 6.2 Layout capture (`ocr_service.py`, `review/layout.py`)

- `ocr_service.group_ocr_boxes(ocr_lines) -> list[OcrLineGroup(text, boxes)]` contains the grouping logic moved
  verbatim from `lines_from_boxes`; `lines_from_boxes` becomes `"\n".join(g.text for g in group_ocr_boxes(...))`
  (byte-identical; LY-01).
- `extract_text_from_pdf` adds `pages[i]["layout"]` without changing any existing key:
  - OCR page: one `LayoutLine` per group: text, bbox = union of its boxes × 72/dpi (points, displayed page),
    tokens `(text, bbox, conf)`.
  - Native page: lines from `page.get_text("words")` grouped by `(block_no, line_no)` in extraction order; bbox =
    union of word rects transformed by `page.rotation_matrix` when `page.rotation != 0`; tokens with conf 1.0.
  - `width`/`height` = `page.rect` (displayed), `unit="pt"`, `method`, `rotation`.
- Images: one page; OCR boxes in pixels of the EXIF-transposed image; `unit="px"`, width/height = image size.
- CSV: no pages; `@row=N` meta (1-based physical line in the file) appended to each canonical line and each
  leftover line by `_delimited_text_to_lines`; `parse_canonical_line` already ignores unknown `@` meta, so rows are
  identical (LY-05). `source_text` = that physical CSV line.

### 6.3 Mapping rows to lines (`review/layout.py`)

- Physical lines are the non-empty stripped lines of `raw_text`, numbered globally in order, page by page (pages are
  separated by blank lines, so numbering is unambiguous).
- OCR pages: the k-th non-empty line of the page text **is** the k-th group (same function).
- Native pages: align the page's text lines with its layout lines by whitespace-normalised equality, two pointers,
  look-ahead ≤ 5 layout lines; an unaligned text line gets no geometry. Target: 100% aligned on the golden samples
  and on dev native reports (LY-03 measures it; misses are investigated, never tolerated by loosening).
- Traced tokenizer: `reassemble_cells_traced` and `parse_lab_text_traced` carry `tuple[int, ...]` line ids through
  reassembly; header lines produce nothing; an `interp` line extends the previous row's ids; a logical line with
  unread parts yields one unread item (its ids, its text, its unread count). `parse_lab_text_ex` and
  `reassemble_cells` call the traced versions and drop the extras (TK-01).
- Row geometry: page = page of its first line id; bbox = union of its lines' bboxes on that page; `source_text` =
  its physical lines joined with `" | "`. Two tests on one line share the line bbox.
- Column-parser rows: page and bbox from the parser (union of the words it used).
- Legacy urine rows: the first layout line (document order) whose normalised text contains the row's value token
  and a name token; none → no geometry (NR-NOLOCATE).

### 6.4 Confidence (FR-7.1)

| Origin | Confidence |
|---|---|
| native text, one physical line | 1.0 |
| native text, ≥ 2 physical lines (reassembled) | 0.85 |
| OCR | minimum Paddle token confidence over the row's lines |
| column parser | 0.85 |
| CSV | 1.0 |
| manual | 1.0 |
| legacy urine | confidence of the located line (as above); 0.5 if not located |
| unread line | the line's reading confidence (native 1.0, OCR minimum token) |

### 6.5 Specimen (`review/specimen.py`)

- From `ParsedRow.section` words: urine, urinary, urinalysis, spot urine, 24-hr/24 hr → `urine`; csf,
  cerebrospinal → `csf`; fluid, pleural, ascitic, peritoneal, synovial, pericardial → `fluid`; stool, semen, sputum,
  swab → `other`; haematology/hematology, biochemistry, chemistry, serum, plasma, blood, cbc, haemogram/hemogram,
  lipid, thyroid, liver/lft, kidney/renal/kft/rft, electrolytes, serology, coagulation, hormone, blood gas/abg,
  diabetes, cardiac, iron, vitamin → `serum`. A heading containing a non-blood word wins ("URINE SPOT
  ELECTROLYTES" → urine).
- Analyte key `urine_*`, `specific_gravity`, `urine_ph` → urine; `csf_*` → csf; legacy urine rows → urine.
- Otherwise: report has no non-blood specimen anywhere → `serum`; else (mixed report) → `unknown` (NR-SPECIMEN).

## 7. Scoring on confirm

### 7.1 `score_confirmed_rows(rows, *, sex, age, patient_id=None, job_id=None, explanation_mode="brief",
unread_line_count=0, history_reader=None) -> ScoringOutput`

`ScoringOutput`: `response: PipelineResponse` and `row_flags: list[str]` aligned with the input rows (a row merged
into a duplicate takes the survivor's flag, as `EngineFloorScorerV0._row_flags` does). Steps:
1. `ParsedRow`s from `parsed_payload` (deep copies) for every row; edits were already merged into the payload at
   PATCH time (§7.2); manual rows carry `build_manual_row` payloads.
2. `analyze_lab_rows(parsed, sex, age, unparsed_numeric_lines=unread_line_count)` (production confirm passes 0: every
   unread line was converted or dismissed).
3. The existing scoring half of `run_report_pipeline` (pipeline.py:1330-1635), unchanged in logic except the inputs
   listed in §7.4: `_scored_to_row`, `_engine_lab_dict`, `analyze_blood_report`, `predict_tabular`, ensemble,
   `apply_risk_floor`, the critical ceiling, differential/explanation, RAG, decorate, history comparison.
4. `lab_values[i]` gains `row_id`, `row_index`, `review_status` (accepted/edited/added), `origin`, `specimen`,
   `source_page`, `source_bbox`, `source_text`, `confidence`, `merged_row_ids` (S9).
5. `PipelineResponse` gains `critical_alerts` (the engine's alerts; default `[]`) and `confirmed: true`.

### 7.2 Edit merge policy (`rows.apply_row_edit`; the same function serves PATCH and the eval)

| Field changed | Payload update | Payload fields cleared |
|---|---|---|
| `name_raw` | `p.name` | — (the analyte is re-resolved at scoring) |
| `value_raw` | `p.value`, `p.qualifier`, `p.text_value`, `p.result_range` from `parse_value_input` | `candidates`, `ambiguity`, `note` |
| `unit_raw` | `p.unit` (None when blank) | `ref_unit` (the range is then read in the result unit) |
| any of `ref_low`, `ref_high`, `ref_text` | `p.ref_low`, `p.ref_high`, `p.ref_text` (formatted when not given); strictness from a `<x`/`>x` text | `sex_ranges`, `age_ranges`, `range_options`, `interpretive_only`, `ref_unit` |
| `printed_flag` | `p.printed_flag` | — |
| `specimen` | `p.specimen` | — |
| any field | — | `warnings` |

`build_manual_row` creates `ParsedRow(name, value…, unit, ref_low, ref_high, ref_text, printed_flag=None,
source="manual", specimen)`. Unread-line conversion = `build_manual_row` from the edited fields, keeping provenance.

### 7.3 The S5 floor (engine change (c))

`ParsedRow.specimen: Optional[str] = None`. In `evaluate._score_row`, right after `match_analyte`: if `p.specimen` is
`urine`, `csf`, `fluid` or `other` and the matched analyte is a blood analyte (key not `urine_*`/`csf_*`, not
`specific_gravity`/`urine_ph`), set `analyte = None` and add the note "specimen <x>: blood reference ranges and
critical limits not applied" (the existing "trust only the report" pattern, evaluate.py:390). A generic `pH` with
specimen urine resolves to `urine_ph`. Specimen `None`, `serum` or `unknown` → unchanged behaviour. Applied at
extraction (inferred specimen) and at scoring (confirmed specimen), so the preliminary flag is what acceptance gives.

### 7.4 Inputs the scorer may use (S1)

| Today (raw text) | P2 scoring input |
|---|---|
| `predict_tabular(lab_dict, raw_text)` | `predict_tabular(lab_dict, confirmed_text)`; `confirmed_text` = one line per confirmed row: `"<name> <value_raw> <unit> (<range>)"` |
| `_explain_report_safe(raw_text, …)` | `confirmed_text` |
| `_run_ner_safe(raw_text)` entities | `{conditions: analyze_blood_report(...)["active_conditions"], medications: [], dates: []}` |
| urine patterns and KB on raw text | `urine.urine_entities_from_rows(confirmed urine rows)` → `_apply_urine_pattern_rules` (made public as `apply_urine_pattern_rules`) → pattern anomalies and urine risk; the KB query uses the pattern names only |
| urine-only branch shows legacy rows unscored | every confirmed row is engine-scored; `panel_type = "urinalysis"` when no confirmed row is a blood row (`_is_blood_row`) |
| `get_patient_history_sync` (all reports) | `history_reader` → confirmed, completed, non-superseded reports of the same owner, excluding this job |

### 7.5 Scoring task outcome

`store.complete_scoring(job_id, response_json)`: one transaction: upsert `reports` (as `upsert_report_result`, with
`status = 'COMPLETED'`), CAS `scoring → completed`. Final failure after retries → CAS `scoring → failed`, generic
error, rows and edits kept; `reopen` is allowed from there.

### 7.6 How an edit changes the result, and why deleted rows cannot leak

- **Edits re-run scoring by construction.** Scoring reads each confirmed row's current `parsed_payload`, which PATCH
  rewrites through `apply_row_edit` in the same transaction as the audit rows. Edits are possible only in
  `awaiting_review`; scoring starts only at confirm, after the last edit, under the same job lock, and confirm must
  quote the latest `revision`. A clinician who spots an error after completion uses reopen (§4.7): the old result is
  marked `SUPERSEDED` (unreadable through the gate), and the next confirm scores the edited rows (AC-1.3, S1-7).
- **Deleted rows are excluded at the only entry point.** `store.load_confirmed_rows` selects
  `kind = 'row' AND status IN ('accepted','edited','added')`; `score_confirmed_rows` never sees `deleted` or
  `pending` rows or unread lines; `reports`, the PDF, QR preview, history and trends are all built from the scoring
  output; the review API still lists deleted rows (status `deleted`) so the clinician can restore them before
  confirm (AC-1.4).

### 7.7 `run_report_pipeline` (kept for tests and the eval only)

Becomes `score_confirmed_rows(accept_as_shown(extract_report(...)), unread_line_count=len(unread))` returning the
`PipelineResponse` (the error and "Insufficient evidence" responses keep their current shapes and messages, with a
generic `error`). Docstring: "TEST/EVAL COMPOSITION — never called by a route or task; enforced by
tests/test_s1_static.py". `run_pipeline` (the unused smart router) gets the same note. Existing tests that call it keep
their clinical expectations; an assertion may change only where §7.4 removes a raw-text signal, and each such change
is listed in the commit message and a DECISIONS line.

## 14. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Playwright needs unreachable CDNs; CI runners differ | system Chrome; integrity-pinned npm tarballs routed in-browser; skip-or-fail switch; local run is the gate evidence |
| Native text lines do not align with word boxes on some PDFs | two-pointer alignment with look-ahead; unaligned rows get NR-NOLOCATE (safe); LY-03 measures; fix causes, never loosen |
| OCR cache invalidated by `ocr_service.py` edits | one cold run (CI ≈ 13 min, full ≈ 2 h); identity tests prove the text is unchanged |
| Existing tests depend on raw-text signals now removed by S1 | §7.7 rule: clinical expectations stay; each changed assertion listed with a DECISIONS line |
| Review burden (M7) and M6 worsen (more triggers, every qualitative row) | expected and declared; M6/M7 are target-only from P3; P3 adds keys and fixes the engine |
| Races: on_success clobbering, dispatch before commit, double confirm, sign-off vs reopen | DB row lock + CAS on every transition; WK-04, WK-08, SC-02, SC-03 |
| Celery result backend leaks values | report tasks return status only; WK-07 |
| Zero tolerance on image M2/M2_post flakes on a cold cache | warm the cache and re-run; never loosen (DECISIONS) |
| A clinician sets the wrong specimen and hides a blood critical | specimen change is an audited edit; the edit form explains "blood critical limits are not applied to urine/CSF"; the row was reviewed by the clinician who confirms |
| Legacy reports become unshareable | declared (S1); re-upload restores the flow; nothing deleted |
| Admins cannot review others' jobs | FR-1.4 owner-only; declared until PLT-01 roles |
| Edits after sign-off are impossible | signed reports are immutable; declared limitation |
| P2 is large | ordered tasks; safety-critical backend first; UI after the API is frozen; no push between T10 and T17 |
| Known P3 gaps stay silent in P2 (e.g. Hb 22 g/dL: 29 % above range, no engine limit) | M2/M2_post report them honestly; P3 adds limits; never hidden by test tuning |

## 15. Decisions to copy into docs/DECISIONS.md (one line each, date 2026-11-22)

1. P2 job states are `queued → extracting → awaiting_review → scoring → completed | failed | low_quality`; the
   database (`async_jobs.status`) is the source of truth for report jobs; every transition is a row-locked CAS; report
   tasks never write status from `on_success`.
2. All report types and all file kinds (PDF, image, CSV) go through review; structured imports are never auto-confirmed
   in P2 (F2's "may" is not taken; the review screen needs one click).
3. Review tables add, beyond FR-1.2: `report_extractions` (job metadata, revision, confirmation stamp), and
   `extracted_rows.kind`, `review_codes`, `prelim_flag`, `parsed_payload`, `version`; origin adds `legacy_urine`.
4. `prelim_flag` is computed and stored for review triggers and the eval but never returned before confirm; the review
   screen shows extracted data, the printed flag and review reasons only (S1).
5. Sign-off de-duplication keeps the earliest row and archives the others in `sign_off_duplicates_archive`; downgrade
   restores them and refuses to drop non-empty review tables unless `VAIDYA_ALLOW_LOSSY_DOWNGRADE=1`.
6. New review endpoints are owner-only with no admin bypass (404), per FR-1.4.
7. Confirm requires the revision the clinician saw; rows use optimistic versions.
8. Accepting a row requires a value, a unit when the analyte needs one (S6), and a specimen when the report is mixed;
   manual rows must state their specimen.
9. Reopen is allowed only before sign-off (or after a scoring failure); signed reports are immutable.
10. Legacy (pre-P2) completed report jobs are not results under S1: result, PDF, sign-off and QR answer 409/403, and
    history/trends exclude them; nothing is deleted.
11. `POST /api/text` is unregistered (it scored unconfirmed free text); the module goes with FR-9.5 in P6.
12. Scoring uses confirmed rows only: model text, RAG query, entities and urine patterns are rebuilt from confirmed
    rows; raw-text NER medications/dates are no longer part of lab results.
13. The extracted row set equals the pre-P2 product's (engine rows, legacy urine rows under today's branch rule) plus
    unread lines; P2 changes flags and metadata, not rows.
14. S5 floor: a row with specimen urine/CSF/fluid/other is never scored against a blood analyte's registry range or
    critical limits (FR-2.3 completes specimen-specific analytes in P3).
15. needs_review triggers are the 19 codes of plan §6.6, including NR-MARKED (markedly abnormal with no registry
    critical limit in that direction) as a safety net for the engine's known missing limits; every qualitative row
    needs review until P3 adds keys.
16. Confidence: native 1.0 (0.85 when reassembled), OCR minimum token confidence, column 0.85, CSV and manual 1.0.
17. Provenance bboxes are in displayed-page points (PDF) or pixels of the EXIF-transposed image; native boxes are
    transformed by `page.rotation_matrix`.
18. Page images: lazily rendered, disk-cached, `Cache-Control: private`, EXIF stripped.
19. `run_report_pipeline` survives only as a test/eval composition; a static test forbids production callers.
20. The two legacy RAG integration tests are re-targeted at the live claim task and the authenticated HTTP flow;
    nothing dead is resurrected; `tasks_rag.py` goes with FR-9.5 (P6).
21. Playwright (Python, pinned in `requirements-e2e.txt`) drives the system Chrome; React/ReactDOM/Babel are served to
    the test browser from integrity-pinned npm tarballs; the UI shell is unchanged.
22. Eval: `ExtractedRowsAdapter`/`confirmed_v1` call the product functions directly; `pre_review_headline` is the
    as-shown confirmation headline computed in the adapter only.
23. Judge tightenings: unread-line coverage needs the same page and vertical overlap when geometry exists (T16 F2);
    `M4_post` ratcheted with the M4 target (LOW-1); zero ratchet tolerance for M2/M2_post on every rendering (LOW-3).
24. Re-baselines: #1 judge-only with v0; #2 adapter switch, accepted only if no test rendering's M1 rises or M2 falls
    and `ext_rows` is unchanged.
25. T16 L9 stays fail-loud (a `ValueError` in `job_record` aborts the run): conservative; unchanged.
26. When no row of kind `row` was extracted, the review screen tells the clinician to check the whole report
    (`review_all`), whether or not unread lines exist; this keeps P1's review_all meaning.
27. Report tasks return status-only payloads to the Celery result backend; results live only in the database (privacy
    and S1).
28. P2 patient demographics are read-only on the Review screen (set at upload); a sex-dependent range without sex stays
    "not assessed" unless the clinician enters the range.
