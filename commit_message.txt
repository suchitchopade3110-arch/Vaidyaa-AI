fix(ci): use dynamic DATABASE_URL for alembic migrations in CI

## What changed
- Updated `alembic/env.py` to override the hardcoded `sqlalchemy.url` in `alembic.ini` with the dynamically generated `settings.DATABASE_URL` from `app.core.config`, replacing the `asyncpg` driver with `psycopg2` for Alembic's synchronous operations.

## Why
- `alembic upgrade head` in CI was failing with `password authentication failed for user "vaidya"`.
- This occurred because `alembic/env.py` was pulling the hardcoded password (`vaidya123`) from `alembic.ini`, while the Postgres service in CI was initialized with `POSTGRES_PASSWORD=ci-only-password`. Injecting the application settings dynamically ensures Alembic uses the same credentials as the application.

## Verification
- Verified the script change dynamically parses `POSTGRES_USER` and `POSTGRES_PASSWORD` from the environment.

## Risk
- Low. This resolves a known credentials discrepancy when running Alembic in CI or other environments using environment variables for configuration.
